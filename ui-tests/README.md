# UI Tests

End-to-end tests that exercise the full text editor by running it as a real
process inside a pseudo-terminal, sending keystrokes through the PTY, and
asserting on the rendered screen state and on-disk file contents.

No additional npm packages are required.  The only external tool is
[`node-gyp`](https://github.com/nodejs/node-gyp), which is fetched
on-demand by `npx` and needs a standard C build toolchain
(`gcc`, `make`, `python3`) plus Linux header `<pty.h>` from the
`libutil-dev` / `libutil-freebsd-dev` package (usually present by default
on Debian/Ubuntu).

## PTY wrapper — how it works

### Why a PTY?

The editor reads raw key events from `stdin` and writes ANSI escape sequences
to `stdout`.  Both behaviours require a real TTY:

- `process.stdin.isTTY` must be `true` for `setRawMode(true)` to work.
- `process.stdout.columns` / `.rows` must reflect the virtual terminal size
  so the editor knows how wide to draw each line.
- ANSI output (cursor positioning, colors) only makes sense when a terminal
  is consuming it.

A plain `child_process.spawn` with `stdio: 'pipe'` sets `isTTY = false`, so
the editor would never enter raw mode.  A pseudo-terminal solves this.

### The C addon (`pty/pty.c`)

The addon is a [Node.js N-API](https://nodejs.org/api/n-api.html) native
module compiled by `node-gyp`.  It wraps seven POSIX functions:

| JS function | C call | Notes |
|---|---|---|
| `spawn(exec, args, cols, rows)` | `forkpty()` | Creates master/slave PTY pair; returns `{ fd, pid }` |
| `write(fd, buffer)` | `write(2)` | Sends bytes to the editor's stdin |
| `read(fd)` | `read(2)` | Non-blocking (master fd has `O_NONBLOCK`); returns `Buffer` or `null` |
| `resize(fd, cols, rows)` | `ioctl(TIOCSWINSZ)` | Sends resize signal to the child |
| `kill(pid, signal)` | `kill(2)` | Sends a signal; `SIGTERM` + `SIGKILL` for cleanup |
| `waitpid(pid, nonblocking?)` | `waitpid(2)` | Reaps the child; returns `{ exited, code }` |
| `close(fd)` | `close(2)` | Closes the master fd |

**`forkpty` internals:** `forkpty()` creates a master/slave PTY pair, calls
`fork()`, and in the child makes the slave TTY the controlling terminal and
standard I/O device before calling `setsid()`.  The parent receives the
master fd through which all I/O is multiplexed.  Setting `O_NONBLOCK` on the
master fd ensures `read()` returns `EAGAIN` rather than blocking, keeping the
Node.js event loop responsive between polls.

**Environment:** The child inherits the parent process environment and then
receives two additional variables:

```c
setenv("TERM", "xterm-256color", 1);
setenv("COLORTERM", "truecolor", 1);
```

These tell the editor it can emit 24-bit RGB ANSI colors, matching what a
real terminal would provide.

### TypeScript wrapper (`tests/PtyProcess.ts`)

`PtyProcess` loads the `.node` addon via `createRequire(import.meta.url)`
(required because the test files are ES modules but native addons are
CommonJS).

The key method is `readOutput(idleMs, maxWaitMs)`:

```
while within maxWaitMs total:
    chunk = native.read(fd)          ← non-blocking
    if chunk:
        accumulate; record last-data timestamp
    else if (time since last data) >= idleMs:
        break                        ← idle window closed
    else:
        await sleep(15)              ← yield to event loop
return accumulated string
```

An idle window of 200–300 ms is enough because the editor re-renders
synchronously on every keystroke (a full-screen repaint arrives in < 5 ms).
Saves are async, so the save tests use 400–500 ms.

## Virtual screen (`tests/TerminalScreen.ts`)

The editor outputs absolute-position ANSI sequences (`ESC[row;colH` followed
by styled text), so tracking what is on screen requires a virtual terminal.

`TerminalScreen` maintains a `rows × cols` grid of characters.  `feed(str)`
walks the string character by character:

- **Printable characters** → written to `grid[cursorRow][cursorCol]`; cursor
  advances.
- **`ESC[row;colH`** → cursor jump (1-indexed → 0-indexed).
- **`ESC[2J`** → grid reset to spaces, cursor → (0,0).
- **`ESC[K`** → erase current row from cursor to end.
- **SGR (`ESC[…m`), cursor visibility (`ESC[?25l/h`), and all other
  sequences** → silently skipped.

Since Node.js decodes UTF-8 before passing the string to `feed()`, every JS
character (including multi-byte glyphs like `│` `─` `●`) is already one code
point and occupies exactly one grid column.

Assertion helpers:

| Method | Purpose |
|---|---|
| `containsText(text)` | Scans every row |
| `containsTextInCols(text, start, end)` | Scans within a column range — used for per-pane checks |
| `getLine(row)` | Returns raw row content |
| `findText(text)` | Returns `{ row, col }` or `null` |
| `dump()` | Returns a numbered grid dump for failure messages |

## How tests interact with the editor

```
Test code                PTY master fd            Editor process
─────────────────────    ──────────────────────   ──────────────────────────
EditorTest.start()  ──→  spawn() [forkpty]   ──→  node dist/index.js [file]
EditorTest.keys()   ──→  write(fd, bytes)    ──→  process.stdin data event
                    ←──  read(fd)            ←──  process.stdout.write(…)
screen.feed(output)      (ANSI escape seqs)       (Renderer.flush)
assertions on screen
```

1. `EditorTest.start()` spawns the editor and reads until the PTY is idle
   (initial render complete).
2. `EditorTest.keys(seq)` writes a key sequence, then reads until idle again
   (post-keystroke render complete).
3. `TerminalScreen.feed()` integrates all received output into the grid.
4. Assertion methods check the grid (or temp-file contents on disk).

## Checking output

### Screen content

```typescript
t.assertContains('Hello World');           // text anywhere on screen
t.assertLineContains(0, '[No File]');      // text on a specific row
t.assertStatusContains('EDIT');            // text on the last row (status bar)
t.assertInCols('LEFT_DATA', 0, 59);       // text in pane 0 (left half, hsplit2)
t.assertInCols('RIGHT_DATA', 60, 120);    // text in pane 1 (right half, hsplit2)
```

### File content on disk

```typescript
const content = readTempFile(file);        // fs.readFileSync wrapper
if (!content.startsWith('expected')) throw new Error(…);
```

Buffer.save() appends a trailing `\n`, so checks use `.startsWith()` rather
than strict equality.

## Adding new tests

1. Create `tests/NN_name.test.ts`.
2. Export `suite: string` and `tests: TestCase[]`.
3. Each test should:
   - Create a fresh temp directory with `createTempDir()`.
   - Use `try … finally { t.cleanup(); removeTempDir(dir); }` to guarantee
     cleanup even on failure.
4. Re-run `node ui-tests/runner.mjs`; the new file is auto-discovered.
